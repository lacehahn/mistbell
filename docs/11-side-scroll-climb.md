# 攀爬段改成 2D 侧视地图（设计确认稿）

## 用户的意图（我的理解）
现在的 3D 攀爬读不出"从低到高"，所以**攀爬整段改成 2D 侧视卷轴**：

1. 玩家从山脚（画面左侧）进入，**2D 横版**：人物在一条向上的山道上走，背景多层视差
2. 先**从左向右爬升**，走到右侧折返点
3. 再**从右向左继续爬升**（回头坡），走到一个竖向石阶下方
4. 石阶**从下往上**一路走上去，到顶部
5. 到达顶部后**转场**（白雾/淡出），**载入现有的 3D 场景**，相机就是现在这个 11.5 m 跟随机位
6. 整个过程基本是 2D 的；只有到了教堂才进 3D

也就是说：**2D 侧视攀爬 → 顶部转场 → 3D 教堂区域**。像《歧路旅人》的世界地图/山路那样，用横版卷轴解决"距离与高度"，3D 只留给教堂的仪式感。

## 技术形态（我的方案）
- 逻辑分辨率 **480×270**，整数倍放大（×4 = 1920×1080），保持颗粒与 3D 部分一致
- 三层视差：远景（天空+远山教堂剪影，0.2×）、中景（山脊 0.5×）、近景（岩石/松树 0.8×）
- 地面用**横向无缝长条**拼：走过的路、路肩、下方岩体断面
- 石阶是**竖向 tile 序列**（同一块反复堆），走上去时相机竖直跟随
- 角色用现有 atlas 的 `left/right` 帧，横版直接可用
- 到达顶部触发转场：0.6 s 白雾淡出 → 载入 3D 场景，落点在现在教堂前的台阶
- 进度条/高度提示可省，改成左上角小字"海拔 2170 m"缓慢变化

## 需要你确认的三点
1. **折返次数**：左→右、再右→左，两次就够，还是要三次（左右左）？
2. **石阶高度**：竖向石阶走多久？（我建议 6–8 秒，约 40–60 级）
3. **2D 段能不能战斗/交互**：现在只做"走路 + 转场"，不做战斗，对吧？
